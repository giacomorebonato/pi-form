# pi-form Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pi extension whose `request_input` tool lets the LLM author a JSON Schema, renders a form from it in the user's default browser, validates the submission with Zod, and returns the data to the agent.

**Architecture:** One custom tool. `execute()` checks the agent's schema against a supported subset, converts it to a Zod schema, starts a token-guarded localhost HTTP server that serves a self-contained form page (vanilla-JS renderer, schema embedded as JSON), opens the default browser, and awaits either a valid submission (resolves with data), abort (Esc), or timeout. Validated object returns as tool-result JSON content.

**Tech Stack:** TypeScript (run via pi's jiti, no build), zod v4, node:http, vitest.

**Spec:** `docs/superpowers/specs/2026-11-10-pi-form-design.md`

## Global Constraints

- Node >= 20. `"type": "module"` in package.json. No build step — pi loads TS via jiti.
- Runtime dependencies: `zod` (^4) only. Dev: `vitest` (^3), `@types/node`. Never list `@earendil-works/*` in `dependencies` (pi maps those imports to its own copies at runtime); a devDependency for editor types is allowed but not required.
- Supported subset (everything else must fail fast with a clear error naming the keyword):
  top-level `type: "object"` with `properties`; per-property: `string` (minLength/maxLength/pattern), `number`/`integer` (minimum/maximum), `boolean`, string `enum`, `array` whose items are string/number/enum-string; exactly one level of nested object; `description`, `default`, `required`.
- Server binds 127.0.0.1 only, ephemeral port, 32-byte random token in `?t=` checked on every request, closes after valid submit / abort / timeout.
- All agent-authored strings (title, description, schema) are untrusted: HTML-escaped when embedded; `</script` sequences neutralized inside the JSON script payload.
- Tool result: `content` = `JSON.stringify(data)`, `details` = `{ title: string; data: Record<string, unknown> }` on success; error/cancel paths return `isError: true` with a short message.
- `executionMode: "sequential"` on the tool — one pending form at a time.
- Test commands run from repo root: `npx vitest run` (all), `npx vitest run test/<file>` (one).

## Review Focus

- Agent schema with unsupported constructs (`oneOf`, array-of-objects, deep nesting, numeric enums) → clear per-path error naming the keyword, never a crash or silent mis-render (Task 1).
- HTML/JS injection through title, description, or schema strings → escaped; `</script` inside a description must not break out of the payload (Task 3).
- Browser hints vs server validation mismatch (pattern/min/max/minLength) → invalid submit returns 422 with `errors: {field: message}`, form displays them, no unvalidated data ever resolves (Task 4).
- Esc-abort or timeout mid-form → server closes, port freed, `form.result` rejects (`aborted` / `timeout`), tool returns error result (Tasks 4, 6).
- Two concurrent `request_input` calls → sequential execution; each form gets its own server + token, no cross-talk (Tasks 4, 6).

Errors are human-readable, path-qualified, e.g. `properties.tags: unsupported keyword "oneOf"`.

`package.json`: name `pi-form`, private, `"type": "module"`, `"pi": { "extensions": ["./index.ts"] }`, scripts `test: "vitest run"`, dependencies `zod ^4`, devDependencies `vitest` + `@types/node`. Then `npm install`.

- [ ] **Step 2: Write failing tests for `checkSupportedSchema`**

Cases (assert both `ok` and exact `errors` entries):
1. Rejects non-object / missing `type: "object"` / missing `properties` (e.g. `["schema must be a JSON Schema object with type \"object\" and \"properties\""]`).
2. Accepts: string with minLength/maxLength/pattern + description + default; integer with minimum/maximum; number; boolean; string enum; array of string; array of number; array of enum (items carry `enum`); one nested object (its properties limited to primitives/enums/arrays — no further nesting); `required` list. 3. Rejects with keyword named: `oneOf`/`anyOf`/`allOf`/`not` (top level and in properties), `$ref`, `patternProperties`, array items that are objects or arrays, nested object inside a nested object (`properties.x.properties.y.properties.z`), non-string enum values, `required` referencing an unknown property, nested objects carrying unsupported keywords too.

### Task 2: JSON Schema subset → Zod converter

**Files:**
- Create: `src/schema-to-zod.ts`
- Test: `test/schema-to-zod.test.ts`

**Interfaces:**
- Consumes: `SupportedSchema` from `src/subset.ts`.
- Produces: `toZodSchema(schema: SupportedSchema): z.ZodType<Record<string, unknown>>`.

- [ ] **Step 1: Write failing tests**

For each supported node type assert parse behavior:
1. Required string with `minLength: 2, maxLength: 10, pattern: "^[a-z]+$"` → accepts `"abc"`, rejects `"a"`, `"abcdefghijklmnop"`, `"ABC"`.
2. Optional property absent → parse of `{}` succeeds without the key.
3. `default` present and value absent → parsed object contains the default.
4. integer `minimum: 1, maximum: 5` → rejects `0.5` (not integer), `6`; number accepts `0.5` within range.
5. enum rejects non-member; array of enum rejects non-member items.
6. nested object: absent + not required → ok; present with bad inner value → error path mentions the inner field (zod flattens errors — assert `.issues` contains the property name).
7. unknown keys in input are stripped (zod object default).

- [ ] **Step 2: Run to verify failure**

Run: `npx vitest run test/schema-to-zod.test.ts` — Expected: FAIL.

- [ ] **Step 3: Implement converter**

Recursive builder: string → `z.string()` + `.min`/`.max`/`.regex`; integer → `z.number().int()` + `.min`/`.max`; number → `z.number()` + min/max; boolean; enum → `z.enum(values)`; arrays → `z.array(itemSchema)`; nested object → `z.object` (one level, guaranteed by `SupportedSchema`). Required → as-is; optional without default → `.optional()`; optional with default → `.default(value)`.

- [ ] **Step 4: Pass + commit**

Run: `npx vitest run` — Expected: PASS (both files). Commit: `feat: json-schema-to-zod converter`.

### Task 3: Self-contained form page

**Files:**
- Create: `src/form-html.ts`
- Test: `test/form-html.test.ts`

**Interfaces:**
- Consumes: `SupportedSchema`.
- Produces: `renderFormPage(payload: FormPayload): string` where `export interface FormPayload { title: string; description?: string; schema: SupportedSchema; token: string; port: number }` (Task 4 embeds this).

- [ ] **Step 1: Write failing tests**

1. Output contains `<title>` with escaped title; title `<script>alert(1)</script>` appears HTML-escaped (assert output does not contain the raw `<script>alert` substring but does contain `&lt;script&gt;`).
2. Embedded JSON payload: schema containing `</script><b>x</b>` in a description renders inert — assert output contains no literal `</script><` after the payload's opening (i.e., the escaping function replaces `<` with `\u003c` in the JSON string).
3. Contains a form element, and the schema's property names appear as field names.
4. Payload carries `token` and `port` values.

- [ ] **Step 2: Run to verify failure** — Run: `npx vitest run test/form-html.test.ts` — Expected: FAIL.

- [ ] **Step 3: Implement `renderFormPage`**

Single exported template string built from: minimal clean CSS (system font stack, max-width ~640px card, light-neutral colors), a `<script type="application/json" id="payload">` block filled with `JSON.stringify(payload)` passed through a `escapeJsonForScript` (replace `<` with `\u003c`, `>` with `\u003e`, `&` with `\u0026`, line separators), and vanilla-JS renderer that reads the payload and builds the DOM: string→text input (minlength/maxlength/pattern attrs), number/integer→number input, boolean→checkbox, enum→select, string/number arrays→repeatable rows with add/remove, enum arrays→checkbox group, nested object→fieldset; `description` → label + help text; `default` pre-filled; required marked. Submit handler: gather values (convert number fields with `Number(...)`; collect arrays), `POST /submit?token=…` as JSON, on `422` render `errors` next to fields, on success replace form with "Submitted — you can close this tab." No framework, no external requests.

- [ ] **Step 4: Pass + commit** — Run: `npx vitest run test/form-html.test.ts` — Expected: PASS. Commit: `feat: form page renderer`.

### Task 4: Token-guarded form server

**Files:**
- Create: `src/server.ts`
- Test: `test/server.test.ts`

**Interfaces:**
- Consumes: `renderFormPage`, `FormPayload`, `toZodSchema`.
- Produces: `startForm(opts: { title: string; description?: string; schema: SupportedSchema; signal?: AbortSignal; timeoutMs?: number }): Promise<FormHandle>` where `export interface FormHandle { url: string; result: Promise<Record<string, unknown>>; close(): void }`. `result` rejects with `Error("aborted")` or `Error("timeout")`; resolves with validated data on successful submit. Resolves only after the listener is up. `close()` idempotent, frees the port.

- [ ] **Step 1: Write failing tests**

Against a live `startForm` (use `127.0.0.1`, ephemeral port, real `fetch`):
1. GET the URL (with correct token) → 200, content-type text/html, body is the form page.
2. GET without/with-wrong token → 404. POST `/submit` without token → 404.
3. POST valid data (per a two-property schema, one with `pattern`) → 200 `{ ok: true, data }`, `form.result` resolves to `data`, subsequent fetch of the URL fails (server closed).
4. POST invalid data → 422 `{ ok: false, errors: { field: message } }`, `form.result` still pending (poll a short timeout with `Promise.race` to assert pending).
5. `close()` after start → `form.result` rejects `aborted`; port released (connect → ECONNREFUSED).
6. AbortSignal already aborted before POST → `result` rejects `aborted`.
7. `timeoutMs: 50` with no submit → rejects `timeout` within ~1s.
8. Two forms started concurrently (no signal) → distinct ports, each token 404s on the other's server (cross-talk check).

- [ ] **Step 2: Run to verify failure** — `npx vitest run test/server.test.ts` — Expected: FAIL.

- [ ] **Step 3: Implement `src/server.ts`**

`node:http` server: every request checks `searchParams.get("t") === token` else 404 (no body info). GET → `renderFormPage({...payload, token, port})`. POST `/submit` → `JSON.parse` body (size-capped ~1 MiB), `toZodSchema(schema).safeParse`, map zod issues to `{ [issue.path[0]]: message }` → 422, or → respond `{ ok: true, data }`, then `close()` + resolve. Token via `crypto.randomBytes(32).toString("base64url")`. Listen on `127.0.0.1:0`. Abort/timeout wire `signal` listener + timer into reject + close. Never throws to caller after resolve.

- [ ] **Step 4: Pass + commit** — Run: `npx vitest run` — Expected: PASS. Commit: `feat: form server`.

### Task 6: Extension entry — `request_input` tool

**Files:**
- Create: `index.ts`
- Test: manual verification (pi run); unit-covered logic lives in Tasks 1–5.

**Interfaces:**
- Consumes: everything above; pi APIs pinned from pi 1.5.2 docs: `pi.registerTool` (fields `name, label, description, promptSnippet, promptGuidelines, parameters, executionMode, renderCall, renderResult, execute`), `Type` from `typebox`, `ctx.ui.setStatus(key, text|undefined)`, `pi.exec`, `ctx.hasUI`.

- [ ] **Step 1: Implement `index.ts`**

`registerTool` with `executionMode: "sequential"`, parameters:
```ts
const params = Type.Object({
  title: Type.String({ description: "Short human-readable form title" }),
  description: Type.Optional(Type.String({ description: "Explain to the user why this input is needed" })),
  schema: Type.Any({ description: "JSON Schema (type: object) for the input you need — see guidelines" }),
  timeoutSeconds: Type.Optional(Type.Number({ description: "Give up after this long; default 600" })),
});
```
`execute` flow: `checkSupportedSchema(params.schema)` → on fail return `{ isError: true, content: text listing errors + "fix the schema and retry", details: { errors } }`; `await startForm({ ...params, signal, timeoutMs: (timeoutSeconds ?? 600) * 1000 })`; `ctx.ui.setStatus("pi-form", \`Form "${title}" waiting in browser — ${form.url} (Esc cancels)\`)` (guard `ctx.hasUI`); `openBrowser(form.url)`; `await form.result`; success → clear status, return `{ content: [{ type: "text", text: JSON.stringify(data) }], details: { title, data } }`. Abort/timeout (catch message) → clear status, `{ isError: true, content: "Form input cancelled (browser form closed)" | "Form input timed out", details: { title } }`.
`promptSnippet`: `"Collect structured input from the human via a browser form"`. `promptGuidelines`: two bullets teaching: use `request_input` when you need structured/multi-field input instead of asking in prose; schema must be the supported subset (object of string/number/boolean/enum/array properties, one nesting level, no oneOf).
`renderCall`: `new Text(theme.fg("accent", \`⏳ Form: ${args.title}\`), 0, 0)`; `renderResult`: compact success `Form submitted: ${title}` or the error text; import `Text` from `@earendil-works/pi-tui`.

- [ ] **Step 2: Load smoke check**

Run: `pi -e "$(pwd)/index.ts" -p "Reply with the word loaded"` — Expected: model replies, no extension-load or jiti errors on stderr. (No `tsc` step: pi runs TS via jiti; host imports resolve inside pi only.)

- [ ] **Step 3: Manual end-to-end verification**

Run `pi -e "$(pwd)/index.ts"`, prompt: `Use request_input to ask me for a book title (required) and a 1-5 integer rating (required).` Expected: default browser opens form with both fields; submit invalid rating → inline error; submit valid → agent continues using the values; TUI status clears. Then repeat, press Esc while form open → tool result shows cancelled, port closed (`lsof -i :<port>` empty).

- [ ] **Step 4: Commit** — `git add index.ts && git commit -m "feat: request_input tool"`
